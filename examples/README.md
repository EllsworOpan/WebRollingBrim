# Original clearance test plate

The bundled model is original geometry created for this project from four rectangular plates. It uses no downloaded meshes or third-party model geometry. `models/clearance-test-plate.stl` is generated by `scripts/generate-demo.mjs`, then sliced with PrusaSlicer **2.9.6** using `demo.ini` to produce `gcodes/clearance-test-plate.gcode`.

The app's **Try the holes & pockets test plate** button loads this file, opens the first-layer view, and resets the brim to diameter 10 mm, width 5 mm, gap 0.1 mm, both toggles off. The 3D view and G-code export also work with it. The supplied G-code has generic settings; **re-slice the STL with your own printer profile before physical printing**. The STL is downloadable from the demo guide in the app.

| Label in first-layer view | Shape | Expected behavior at diameter 10 mm |
| --- | --- | --- |
| A, upper left | 20 × 20 mm enclosed hole | Interior receives brim only with **Inside enclosed holes** on. |
| B, upper right | 20 × 20 mm chamber with a 4 mm entrance | Interior receives brim only with **Inside narrow-entry pockets** on. The middle of the narrow throat stays clear. |
| C, lower left | 4 × 4 mm enclosed hole | Interior stays clear with either or both toggles on. |
| D, lower right | 20 mm wide open entrance | Interior is reachable from the exterior, so it receives brim with both toggles off. |

Try diameter **3 mm**: B becomes reachable without the pocket toggle, and C receives brim when holes are enabled. Increasing brim width changes the band width, not which regions the circle can enter. At larger diameters, spaces **between** the separate plates can also become narrow-entry pockets; the counts describe connected regions where a circle centre fits, not a count of named shapes.

## Reproduce the assets

After `npm ci`, generate the small binary STL:

```sh
node scripts/generate-demo.mjs
```

Slice with PrusaSlicer 2.9.6 (adjust the executable path for your system):

```powershell
& 'C:\Program Files\Prusa3D\PrusaSlicer\prusa-slicer-console.exe' --datadir .local/prusaslicer-demo --load examples/demo.ini --center 70,70 --export-gcode --output examples/gcodes/clearance-test-plate.gcode examples/models/clearance-test-plate.stl
```

The isolated data directory keeps fixture generation separate from personal slicer presets. Regeneration may change the slicer's generation timestamp. CI uses the checked-in assets and does not need PrusaSlicer installed.

The matching `gcodes/clearance-test-plate.bgcode` is generated from the same original model/profile with PrusaSlicer 2.9.6:

```powershell
& 'C:\Program Files\Prusa3D\PrusaSlicer\prusa-slicer-console.exe' --datadir .local/prusaslicer-demo --load examples/demo.ini --center 70,70 --binary-gcode --thumbnails '32x32/PNG' --export-gcode --output examples/gcodes/clearance-test-plate.bgcode examples/models/clearance-test-plate.stl
```

It exercises real heatshrink 12/4, MeatPack with comments, DEFLATE metadata and CRC32. Binary regressions compare its paths/settings with the text fixture, verify the exported file using a separate container decoder, and preserve original decoded commands and untouched binary blocks. Synthetic fixtures also cover the other codecs, thumbnails, optional CRCs, malformed input and the runtime command allowlist. This binary fixture is for tests; the in-app sample remains the text version.

## Tests and private samples

`gcodes/Shape-Box_0.2mm_PLA_V2_40m.gcode` is the user-supplied PrusaSlicer box reference, preserved verbatim. It includes a separate skirt followed by eleven brim loops at approximately 0.437 mm spacing. Its brim transitions are short XY moves without retraction or lift. The toolpath regression checks that spacing, sequencing, and every loop's straight-edge positions (within 0.003 mm). It also measures the remaining corner approximation separately (about 0.12 mm maximum), without treating different seam locations as a geometry mismatch. This reference is used in tests, not bundled as a website demo. Its existing brim remains protected from overlap when opened normally in the app.

`tests/box-reference.test.ts` compares the reference's 20 mm/s extrusion and 300 mm/s step feeds, measures extrusion per millimetre directly from its commands, and replays the original first-layer continuation after insertion. It verifies that the required feed restoration is present and all original bytes survive. It also records intentional differences: our insertion inherits the current acceleration instead of switching it for travel, and uses explicit retract/lift rather than the source's wipe and combined XYZ travel. The reference's `infill_overlap = 15%` is preserved as metadata; changing it alone must not change generated brim spacing or extrusion.

`npm run check` covers all four toggle combinations through actual sliced first-layer geometry and exported G-code, using independent point-to-segment distances to check deposited beads. Additional analytic tests cover exact-fit thresholds, nested islands, connected chambers within a closed hole, pockets formed between disconnected parts, gap/width independence, and restoration after switching toggles off. A generated 400,000-move fixture exercises large-file parsing without an external model dependency.

Keep personal or third-party G-code in `.local/gcodes/`, which is excluded from Git and Docker. Run the optional local regression against a compatible file:

```powershell
$env:ROLLING_BRIM_TEST_GCODE = (Resolve-Path '.local/gcodes/your-print.gcode').Path
npm run check
Remove-Item Env:ROLLING_BRIM_TEST_GCODE
```

Binary samples with reviewable startup concerns can be checked with `ROLLING_BRIM_TEST_BGCODE`. This test explicitly accepts only the parsed concerns to exercise round-trip preservation; it still rejects hard blockers. It does not approve the file for printing:

```powershell
$env:ROLLING_BRIM_TEST_BGCODE = (Resolve-Path '.local/gcodes/your-print.bgcode').Path
npm run check
Remove-Item Env:ROLLING_BRIM_TEST_BGCODE
```
